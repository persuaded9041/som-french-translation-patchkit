# 02 - 9-character names + French/extended row

Extends the Name Entry screen while preserving the original fixed-width renderer.

## Behavior

- Names can contain up to **9 characters** instead of 6.
- Four selectable rows are displayed:
  1. `ABCDEFGHIJKLMNOPQRSTUVWXYZ`
  2. `abcdefghijklmnopqrstuvwxyz`
  3. digits / punctuation / symbols
  4. `Çàâçéèêëîïôùû♪°;`
- The cursor opens on the uppercase row and moves across all four rows.
- Blank cells on the fourth row are encoded as `$80` spaces and count toward
  the 9-character limit.
- The lower French help text is bound by ROM-position IDs to the clean-USA
  `name_entry.help` rows in root `assets/interface_text.json`.

## Sources

- `assets/naming_characters.txt`: component-local four-row character grid.
- root `assets/interface_text.json`: clean-USA Name Entry help source.
- root `translations/interface_text_french.json`: sparse French translations for the validated help rows.
- `shared/french_charset/french_glyphs.png`: canonical editable artwork for
  French characters plus `♪`, `°` and `;`.
- `shared/name_dte.py`: Name Entry / PLAYER_NAME-specific direct/DTE router used by this component.
- `src/patch_data.py`: exact machine-code/data payloads consumed by the builder.
- `src/*.asm`: readable 65C816/data representation of the emitted changes.
- `docs/MEMORY_MAP.md`: ROM allocations and hooks.

Root source assets are regenerated from a clean USA ROM with
`tools/extract_text.py`. `build_patch.py` remains the executable source of truth;
it verifies the canonical source asset against the ROM and resolves the French
text by stable source ID before generating the patch.

## Component-specific charset constraint

Name Entry keeps `$E1-$E5` untouched because those slots are used by original
Name Entry graphics. Its selectable direct glyphs are therefore the historical
`$D4-$E0` French range plus the disjoint shared assignments `$D3=♪`, `$E6=°`
and `$E7=;`.

Ordinary event text retains the `$E1` DTE boundary in a standalone component-02
build. The relocated Name Entry resource in bank `$E4` and the temporary
`PLAYER_NAME` source at `$7E:A22F` use `$E8`, so `♪`, `°` and `;` remain direct
on the naming screen and when the chosen name is expanded later. Other parser
sources keep the legacy boundary. In a full build, component 06/08 owns the
shared parser hook and applies the same bank-`$E4` exception.

## Extended-symbol runtime checkpoint

Runtime testing validates `$D3=♪`, `$E6=°` and `$E7=;` on the fourth Name Entry
row and in the selected name. An earlier probe rendered `$E6/$E7` as stock DTE
pairs `at` / `ac`; tracing showed that the displayed grid itself is parsed from
the relocated bank-`$E4` resource. The validated route therefore gives both that
bank and the temporary `PLAYER_NAME` source the `$E8` direct range, in the
standalone 02 router and in the full 06/08 router. Ordinary parser sources keep
their legacy threshold.

## Name Entry resource

The generated resource is relocated to `$E4:4000`:

```text
+$0000  uppercase row     60 bytes
+$003C  lowercase row     60 bytes
+$0078  symbols row       60 bytes
+$00B4  extended row      60 bytes
+$00F0  French help text  variable
+...    16 zero guard bytes
```

Each character row contains 30 two-byte cells. Framing and terminator cells are
generated by the builder; editable files contain only useful characters or
translations.
